Station 1

Klassen, Objekte & Attribute

🧠 Der Wissens-Snack

  • Die Klasse: Ist nur der Bauplan im Code.
    Analogie: Ein 3D-Modell in einer CAD-Software. Es ist nur eine Beschreibung, existiert aber in der echten Welt noch nicht.
  • Das Objekt (Instanz): Ist das fertige Produkt.
    Analogie: Der fertige 3D-Druck. Er nimmt nun tatsächlichen Platz im Arbeitsspeicher ein.
  • Die Referenzvariable: Speichert nicht das Objekt, sondern nur seine Speicheradresse!
    Analogie: Ein Lesezeichen im Browser. Es speichert nicht die ganze Webseite, sondern nur den Pfad (URL) dorthin.

Der Code-Bauplan

public class Monster { String name; // Attribut 1 (Eigenschaft) int lebenspunkte; // Attribut 2 } // In einer anderen Klasse (Arena) innerhalb der main-Methode: Monster meinMonster = new Monster(); // Objekt erschaffen meinMonster.name = "Feuer-Blob"; // Punktnotation

💻 Deine Aufgaben in IntelliJ

  1. Erstelle ein neues Projekt namens MonsterArena.
  2. Lege die Klasse Monster an (mit den Attributen name, lebenspunkte und angriffskraft).
  3. Lege eine Klasse Arena mit einer public static void main(String[] args) an.
  4. Erschaffe dort ein Monster-Objekt und weise ihm Werte über die Punktnotation zu.
  5. Das Speicherexperiment: Lass dir das Monster direkt ausgeben:
    System.out.println(meinMonster);
    Betrachte die kryptische Ausgabe (die Speicheradresse!).

⭐ Bonusaufgabe für Schnelle: Der Klon-Irrtum

Tippe folgenden Code ab:

Monster zweitesMonster = meinMonster;
zweitesMonster.name = "Eis-Drache";
System.out.println(meinMonster.name);

Welcher Name hat nun das ERSTE Monster? Was genau bedeutet das '=' bei Referenzvariablen?

Station 2

Methoden & Objekt-Interaktion

🧠 Der Wissens-Snack

Bisher sind unsere Objekte reine Datenspeicher. Sie brauchen Verhalten. Das lösen wir mit Methoden. Besonders spannend: Wir können die Referenz eines anderen Objekts als Parameter übergeben, damit die Objekte miteinander interagieren (z.B. kämpfen) können!

public void angreifen(Monster gegner) { // Eigene Kraft vom Leben des gegnerischen Objekts abziehen gegner.lebenspunkte = gegner.lebenspunkte - angriffskraft; } // Aufruf in der Arena: m1 führt aus, m2 ist das Ziel m1.angreifen(m2);

💻 Deine Aufgaben in IntelliJ

  1. Baue die Methoden heilen() und angreifen(Monster gegner) in deine Monster-Klasse ein.
  2. Erstelle in der Arena zwei verschiedene Monster.
  3. Lass sie abwechselnd angreifen und heilen.
  4. Nutze System.out.println(...), um den Kampfverlauf und die verbleibenden Lebenspunkte auf der Konsole zu protokollieren.

Station 3

Konstruktoren & die Geburtsstunde

🧠 Der Wissens-Snack

Fehlerquelle: Wir könnten vergessen, einem Objekt nach dem new Werte zu geben. Ein Konstruktor erzwingt einen sicheren Startzustand bei der Erschaffung.

  • Er wird genau einmal bei new aufgerufen.
  • Er heißt exakt wie die Klasse und hat keinen Rückgabetyp.
  • Wir nutzen this, um Klassenattribute von übergebenen Parametern zu unterscheiden.
public class Monster { String name; int lebenspunkte; // Der Konstruktor public Monster(String name, int lebenspunkte) { this.name = name; // mein Attribut = Parameter this.lebenspunkte = lebenspunkte; } }

💻 Deine Aufgaben in IntelliJ

  1. Lösche in der Arena deine bisherigen manuellen Zuweisungen (m1.name = ...).
  2. Shortcut: Klicke in der Klasse Monster in eine leere Zeile, drücke Alt + Einfügen (Mac: Cmd + N) -> Constructor. Markiere alle Attribute und drücke Enter.
  3. Repariere die Arena: Übergebe die Startwerte nun zwingend in den Klammern bei new Monster(...).

⭐ Bonusaufgabe für Schnelle: Überladung

Eine Klasse kann mehrere Konstruktoren besitzen. Schreibe manuell einen zweiten Konstruktor, der *nur* den Namen als Parameter verlangt und die Lebenspunkte des Monsters im Codeblock automatisch auf 100 setzt.

Station 4

Datenkapselung & Packages

🧠 Der Wissens-Snack

Geheimnisprinzip: Direkter Zugriff auf Attribute muss verhindert werden, sonst könnte jemand in der Arena schreiben: m1.lebenspunkte = -500;.
Wir setzen Attribute auf private und erlauben den Zugriff nur über kontrollierte public Methoden, sogenannte Getter und Setter. Zudem organisieren wir das Projekt in Ordnern (Packages).

private int lebenspunkte; // 🔐 Streng geheim! // Der Türsteher (Setter) public void setLebenspunkte(int neuerWert) { if (neuerWert >= 0) { // Sicherheits-Check! this.lebenspunkte = neuerWert; } }

💻 Deine Aufgaben in IntelliJ

  1. Erstelle im Projektbaum zwei neue Packages (Ordner): arena und wesen.
  2. Verschiebe Arena.java nach arena und Monster.java nach wesen.
  3. Setze alle Attribute in Monster auf private. (In der Arena entstehen nun Fehler - das ist gewollt!).
  4. Shortcut: Generiere mit Alt + Einfügen -> Getter and Setter die Methoden für alle Attribute.
  5. Repariere die Arena, indem du dort nun die Methoden (z.B. getName()) statt der direkten Attribute nutzt.

⭐ Bonusaufgabe für Schnelle

Baue einen Logik-Check im Setter für die angriffskraft ein: Die Kraft darf nie größer als 50 gesetzt werden!

Station 5

Vererbung (Evolution)

🧠 Der Wissens-Snack

Um Code-Wiederholungen zu vermeiden, können spezielle Monster-Klassen von unserer Basis-Klasse erben (Schlüsselwort: extends).
Wichtig: Damit die Kind-Klasse auf die Attribute der Eltern zugreifen darf, müssen diese in der Basisklasse von private auf protected geändert werden! Existierende Methoden können mit @Override neu geschrieben werden.

public class FeuerMonster extends Monster { private int feuerSchaden; public FeuerMonster(String name, int lp, int feuerSchaden) { super(name, lp); // Ruft den Konstruktor von Monster auf this.feuerSchaden = feuerSchaden; } }

💻 Deine Aufgaben in IntelliJ

  1. Ändere die Modifikatoren in Monster von private auf protected.
  2. Erstelle die Klasse FeuerMonster und lass sie erben (extends Monster).
  3. Lass in deiner Arena ein klassisches Monster gegen dein neues Feuermonster antreten.

⭐ Bonusaufgabe für Schnelle

Erstelle ein WasserMonster. Überschreibe dessen heilen()-Methode (mit @Override) so, dass es sich doppelt so stark heilt wie ein normales Monster!
