Station 1

Klassen, Objekte & Attribute

🧠 Der Wissens-Snack

  • Die Klasse: Ist der abstrakte Bauplan im Code. Er definiert die Struktur, verbraucht aber noch keinen Platz für Daten.
  • Das Objekt (Instanz): Wenn wir aus dem Bauplan ein konkretes Produkt herstellen, nennen wir das Objekt oder Instanz. Eine Instanz existiert wirklich im Arbeitsspeicher deines Computers. Man nennt den Vorgang der Erschaffung deshalb "Instanziierung".
  • Die Referenzvariable: Speichert nicht das Objekt selbst, sondern nur seine Speicheradresse! (Analogie: Ein Lesezeichen im Browser. Es speichert nicht die Webseite, sondern nur den Pfad dorthin).

💡 Alltags-Beispiel zur Veranschaulichung

Die Klasse Auto ist der allgemeine Bauplan bei VW. Eine Instanz (das Objekt) ist dein spezifischer, roter Golf, der bei dir in der Einfahrt steht.

public class Auto {
    String farbe;
    String kennzeichen;
}

// Aus dem Bauplan eine Instanz (ein konkretes Objekt) erstellen:
Auto meinGolf = new Auto();
meinGolf.farbe = "Rot";

Dein Code für die Arena

public class Monster {
    String name;          // Attribut 1 (Eigenschaft)
    int lebenspunkte;     // Attribut 2
    int angriffskraft;    // Attribut 3
}

// In einer anderen Klasse (Arena) innerhalb der main-Methode:
Monster meinMonster = new Monster();
meinMonster.name = "Feuer-Blob";   // Über die Punktnotation Werte zuweisen

  5. Das Speicherexperiment: Lass dir das Monster direkt ausgeben:

    Betrachte die kryptische Ausgabe (die Speicheradresse!).

Station 2

Methoden & Objekt-Interaktion

🧠 Der Wissens-Snack

Bisher sind unsere Objekte reine Datenspeicher. Sie brauchen Verhalten (Fähigkeiten). Das lösen wir mit Methoden. Besonders spannend wird es, wenn wir die Referenz eines anderen Objekts als Parameter übergeben – so können Objekte miteinander interagieren!

Das Schlüsselwort this: Wenn ein Objekt eine Methode ausführt, bedeutet this (englisch für "dieses") immer "ich selbst". Es verweist auf das Objekt, das die Methode gerade aufgerufen hat.

💡 Alltags-Beispiel zur Veranschaulichung

Zwei Bankkonten tauschen Geld aus. Konto A ruft seine Methode ueberweisen(...) auf und übergibt Konto B als Ziel-Objekt.

public class Bankkonto {
    int kontostand;

    // Methode, die ein anderes Konto-Objekt als Parameter erwartet
    public void ueberweisen(Bankkonto zielKonto, int betrag) {
        // "Mein" (this) Kontostand sinkt, der vom Ziel-Konto steigt
        this.kontostand = this.kontostand - betrag;
        zielKonto.kontostand = zielKonto.kontostand + betrag;
    }
}

Dein Code für die Arena

// Neues Attribut (oben in der Klasse bei den anderen ergänzen!)
int heilungskraft;

public void angreifen(Monster gegner) {
    // 'this' ist der Angreifer, 'gegner' ist das Ziel
    gegner.lebenspunkte = gegner.lebenspunkte - this.angriffskraft;
}

public void heilen() {
    // Das Monster heilt sich selbst mit seiner eigenen Heilungskraft
    this.lebenspunkte = this.lebenspunkte + this.heilungskraft;
}

// Aufruf in der Arena: m1 führt die Aktion aus, m2 ist das Ziel
m1.angreifen(m2);

💻 Deine Aufgaben in IntelliJ

  1. Ergänze in deiner Klasse Monster das neue Attribut int heilungskraft;
  2. Baue die beiden Methoden heilen() und angreifen(Monster gegner) in deine Monster-Klasse ein.
  3. Erstelle in der Arena zwei verschiedene Monster-Instanzen und gib ihnen Werte für ihre Attribute.
  4. Lass sie in der main-Methode abwechselnd angreifen und heilen.
  5. Nutze System.out.println(...), um den Kampfverlauf und die verbleibenden Lebenspunkte auf der Konsole zu protokollieren.

Station 3

Konstruktoren

🧠 Der Wissens-Snack

Ein Objekt sollte nie "unfertig" sein. Ein Konstruktor erzwingt einen definierten Startzustand bei der Erschaffung.

  • Er wird genau einmal bei dem new-Befehl aufgerufen.
  • Er heißt exakt wie die Klasse und hat keinen Rückgabetyp.
  • Wir nutzen this, um unsere eigenen Attribute von den übergebenen Parametern (die oft denselben Namen haben) zu unterscheiden.

💡 Alltags-Beispiel zur Veranschaulichung

Ein Benutzer-Account darf im System gar nicht erst existieren, wenn er keine E-Mail hat. Der Konstruktor zwingt uns, die Daten sofort bei der Erstellung mitzuliefern.

public class Benutzer {
    String email;

    // Der Konstruktor zwingt zur sofortigen Übergabe
    public Benutzer(String email) {
        this.email = email;
    }
}

// Instanziierung ist jetzt nur noch mit Parameter möglich!
Benutzer user1 = new Benutzer("test@schule.de");

Dein Code für die Arena

public class Monster {
    String name;
    int lebenspunkte;
    int angriffskraft;
    int heilungskraft;

    // Der Konstruktor für unsere Monster
    public Monster(String name, int lebenspunkte, int angriffskraft) {
        this.name = name;
        this.lebenspunkte = lebenspunkte;
        this.angriffskraft = angriffskraft;
        // heilungskraft könnte man hier ebenfalls ergänzen
    }
}

💻 Deine Aufgaben in IntelliJ

  1. Lösche in der Arena deine bisherigen, zeilenweisen Zuweisungen (m1.name = ...).
  2. Shortcut: Klicke in der Klasse Monster in eine leere Zeile, drücke Alt + Einfügen (Mac: Cmd + N) -> Constructor. Markiere alle Attribute und drücke Enter.
  3. Repariere die Arena: Du musst die Startwerte nun zwingend in den Klammern bei new Monster(...) übergeben.

Station 4

Datenkapselung & Packages

🧠 Der Wissens-Snack

Geheimnisprinzip & Zugriffsmodifikatoren: Direkter Zugriff auf Attribute muss verhindert werden, da man die Daten sonst von außen auf unsinnige Werte setzen könnte. Wir steuern die Sichtbarkeit von Attributen und Methoden mit Schlüsselwörtern:

  • private: Streng geheim! Nur die Klasse selbst darf das Element sehen und ändern.
  • public: Öffentlich! Jeder darf von überall auf das Element zugreifen.
  • protected: Familiengeheimnis. Nur das eigene Package und erbende Klassen dürfen zugreifen (mehr dazu in Station 5).

Was bringen Packages? Wenn Programme größer werden, reicht es nicht, alle Dateien in einen Ordner zu werfen. Wir sortieren Klassen in sogenannte Packages (Ordner-Strukturen, z.B. wesen und arena). Das schafft Übersicht, verhindert Namenskonflikte und stärkt die Sicherheit, da wir Klassen so logisch voneinander abschotten.

💡 Alltags-Beispiel zur Veranschaulichung

Bei einem Smartphone darf der Akku nie auf über 100% geladen werden. Ein direkter Zugriff (meinHandy.akkuStand = 500;) wird durch private blockiert. Der Setter ist der "Türsteher".

public class Smartphone {
    private int akkuStand; // Sicher versteckt

    // Der Setter kontrolliert die Eingabe
    public void setAkkuStand(int ladung) {
        if (ladung <= 100 && ladung >= 0) {
            this.akkuStand = ladung;
        }
    }
    
    // Der Getter lässt uns den Wert sicher auslesen
    public int getAkkuStand() {
        return this.akkuStand;
    }
}

Dein Code für die Arena

private int lebenspunkte; // 🔐 Streng geheim!

// Getter (Lesen)
public int getLebenspunkte() {
    return this.lebenspunkte;
}

// Setter (Ändern kontrolliert erlauben)
public void setLebenspunkte(int neuerWert) {
    if (neuerWert >= 0) {  // Check: Leben darf nicht negativ sein
        this.lebenspunkte = neuerWert;
    }
}

// ----------------------------------------------------
// So greifst du ab jetzt in der Arena auf Monster zu:
// ----------------------------------------------------
Monster m1 = new Monster("Ork", 100, 20);

// m1.lebenspunkte = -500;              // ❌ GEHT NICHT MEHR (Da private!)
m1.setLebenspunkte(80);                 // ✅ Richtig: Ändern über den Setter
System.out.println(m1.getLebenspunkte()); // ✅ Richtig: Lesen über den Getter

  1. Erstelle im Projektbaum zwei neue Packages (Ordner): arena und wesen.
  2. Verschiebe Arena.java nach arena und Monster.java nach wesen.
  3. Setze alle Attribute in Monster auf private. (In der Arena entstehen nun absichtlich Fehler).
  4. Shortcut: Generiere mit Alt + Einfügen -> Getter and Setter die Methoden für alle Attribute.
  5. Repariere die Arena, indem du dort nun die Methoden (z.B. m1.getName()) statt der direkten Attribute nutzt.

Station 5

Vererbung (Evolution)

🧠 Der Wissens-Snack

Um doppelten Code zu vermeiden, können spezielle Klassen von einer Basis-Klasse erben (Schlüsselwort: extends).
Damit die erbende Klasse auf die geschützten Attribute der Basisklasse zugreifen kann, werden diese von private auf protected gesetzt.

💡 Alltags-Beispiel zur Veranschaulichung

Ein Elektro-Auto hat alles, was ein normales Fahrzeug auch hat (z.B. Geschwindigkeit), bringt aber noch eine Batterie-Kapazität mit.

public class Fahrzeug {
    protected int geschwindigkeit; // protected erlaubt Zugriff durch Kinder
}

public class ElektroAuto extends Fahrzeug {
    private int batterieKapazitaet; // Eigenes Attribut

    public void beschleunigen() {
        // Kann auf geerbte Attribute zugreifen!
        this.geschwindigkeit = this.geschwindigkeit + 10;
    }
}

Dein Code für die Arena

public class FeuerMonster extends Monster {
    private int feuerSchaden;

    public FeuerMonster(String name, int lp, int feuerSchaden) {
        super(name, lp, 15); // Ruft den Konstruktor der Basisklasse (Monster) auf!
        this.feuerSchaden = feuerSchaden;
    }
}

💻 Deine Aufgaben in IntelliJ

  1. Ändere die Modifikatoren in deiner Klasse Monster von private auf protected.
  2. Erstelle die Klasse FeuerMonster und lass sie erben (extends Monster).
  3. Lass in deiner Arena ein klassisches Monster gegen dein neues Feuermonster antreten.

Station 6

Open World!

🚀 Zeit für deine Ideen!

Du hast nun alle wichtigen Werkzeuge der Objektorientierung kennengelernt. Jetzt bist du der Spieledesigner! Die Arena gehört dir. Erweitere dein Projekt nach Belieben und mache die Kämpfe spannender.

💡 Ideen-Kiste für Erweiterungen

🎲 Zufallsschaden

Statt immer denselben Schaden zu machen, könnte die Angriffskraft einen Zufallswert zwischen einem Minimum und Maximum haben.
(Tipp: Nutze Math.random())

💨 Ausweichen

Beim Angriff wird gewürfelt: Es besteht eine 20% Chance, dass das angegriffene Monster dem Schlag komplett ausweicht und 0 Schaden nimmt.

💥 Kritischer Treffer

Mit einer gewissen Wahrscheinlichkeit trifft ein Angriff eine Schwachstelle und richtet den doppelten Schaden an!

🔄 Die Kampf-Schleife

Nutze eine while-Schleife in deiner Arena, in der sich die Monster so lange gegenseitig angreifen, bis die Lebenspunkte eines Monsters auf 0 oder darunter fallen.

🧪 Heiltränke (Items) als neue Objekte

Erstelle eine völlig neue Klasse Heiltrank. Ein Monster könnte eine Methode trankTrinken(Heiltrank trank) haben, um sich zu heilen, wodurch das Objekt trank aufgebraucht wird.
